# 影视预演流水线 Skill

核心：预演决定镜头与动作，目标风格参考决定最终外观。成片可以是真人、3D 写实、2D 卡通等，不默认真人化；几何占位体不是最终角色、道具或场景。

流程：创意 → 实际查看 Higgsfield 参考并提炼运镜标准 → 编剧稿 → 导演分镜、调度与独立审稿关卡 → Blender Blockout / Playblast → 导演意图及 Higgsfield 对照检查、修正与复检 → 目标风格参考审核 → Seedance 2.5 提示词审核 → LiClick 生成 → 运镜、动作与风格联合验收。

Higgsfield 贯穿运镜设计与验收，职责为 **运镜参考和验收标准**，不是生图、生视频或必需的文字分镜 API。

## 职责与必用技能

| 环节 | 执行者与交付 |
|---|---|
| 导演分镜 | Codex 使用 screenplay-expert，写剧情、交互、空间、镜头与动作因果，保存导演脚本及 storyboard.json |
| 运镜参考和验收标准 | 分析可查看的 Higgsfield 参考片及指定时间段，形成可观察的镜头标准，记录来源与查看范围 |
| 相机运动实现 | Blender MCP 建立低模空间、主体动作与相机关键帧，导出 Playblast，不承担最终风格渲染 |
| 目标风格 | Codex 整理用户素材；需要新生成角色、场景、道具或首帧资产图时统一使用 imagegen，交用户审核 |
| 2.5 提示词 | Codex 使用 seedance-25-rules 转换确认的导演意图、预演和参考素材，逐一绑定并自检 |
| 最终视频 | 仅 LiClick 调用已核实的 Seedance 版本生成；用户拼写 licklick 也指 LiClick |
| 验收 | Codex 检查运镜、动作、风格和技术指标；最终选择由用户确认 |

导演与提示词专家是 Codex 执行的专业规则，不自动代表独立模型或代理。未实际调用时，不声称 Higgsfield 写了分镜或输出了轨迹。

分镜阶段前必须完整读取当前技能目录中的 screenplay-expert。2.5 提示词阶段前必须读取 seedance-25-rules 及其要求的核心规则、白模/多素材相关章节。提交前读取 lilclick-ai 和相关 API 文档。复用本作品已读取的上下文；技能缺失时说明，不虚称使用或自行安装。

导演规则用于实现用户剧情，不得把已确认剧情当模板改写。已有批准分镜、预演或参考，从对应阶段继续，只审核受变更影响的部分。

## 不变边界

- 全程禁止 Higgsfield generate_video，也禁止 Higgsfield 生图及内部触发生图/视频的分镜功能。
- 最终视频只走 LiClick。不得使用旧 my-seedance、直接供应商接口或其他视频平台替代。assets/seedance-mcp-server.js 保持非活动，不安装或执行。
- Blender 仅做简单网格、平涂材质的几何预演：简化外观，保留表达与检查动作所需的最低结构。所有使用本 Skill 的题材和目标风格均适用，不为消除低模残留擅自升级成最终渲染流程，也不删除必要动作结构。
- 所有新制作并交付的素材默认采用 9:16 竖屏，包括分镜图、布局检查图、角色/场景参考图、首帧、Blender Playblast 和最终视频；仅在用户明确指定其他比例时覆盖，不因检查用途擅自改为横屏。已有外部参考不强制裁改。
- 从构图阶段按 9:16 设置相机和画布，不把横版图直接拉伸或裁掉关键动作充当竖版。导出后核验实际宽高比为 9:16（如 540×960、720×1280 或 1080×1920），确保接触点、主体全身及 UI 在画内。
- 预演保持 24 fps。提交仅使用接口支持的参数；不能显式设定 24 fps 时说明限制，不伪造字段，结果检查实际帧率。
- 预演必须无音轨：Blender Playblast 的导出、交付和上传参考均使用无声视频，不能只把播放器静音。复用旧有声预演时另存移除音轨的副本，保留原文件并核验副本不存在音频流。Seedance 提示词只绑定预演的视觉动作、空间与运镜，不继承其音乐或声音节奏；最终成片的声音按用户要求单独生成，本规则不要求最终视频静音。
- 保留用户确认的风格、运镜、时长、比例、数量、模型与素材。支持多风格不代表同一作品可无授权混用风格。
- 上传和付费生成前确认确切素材、服务/版本、数量、参数与调用范围。已有明确授权无需重复问；审图同意不等于付费生成授权。
- 不自动重试失败、失踪或视觉不合格任务；保存编号和结果，诊断后取得新授权。修改 Skill 不代表重提当前任务。
- 不暴露凭据，不覆盖已确认素材，不将失败候选包装为已接受成片。

## 按阶段检查

只检查当前要执行的阶段，报告 PASS / FAIL / UNVERIFIED / NOT NEEDED。仅更新 Skill 时不启动生产检查或生成。

- Higgsfield 对照是必做审核关卡，不是交付时的免责声明。先查找本作品已有参考及可用的只读来源，实际查看相关片段并记录来源和时间范围；工具不可用时可以查看可访问的参考视频，不以安装或登录成功代替效果检查。
- 无可查看参考或访问受限时，主动查找本作品已有素材、可用只读目录及可访问预览；确实无法取得时及时报告具体缺口并索取片段/链接。仅阻止依赖缺失参考的审核放行及下游付费生成，不停止已获授权、原因明确的本地修正。不得先制作完整预演再以 UNVERIFIED 说明补手续。诊断草案不能作为通过审核的预演。只有用户明确更改本项规则才可跳过；“继续”“可以”“直接出视频”或对局部动作的认可不构成豁免。
- 无需 Higgsfield MCP 安装、登录或纯文字工具才能写本地分镜。已核实的只读描述可辅助理解，但预设名称不能代替观看效果。
- 新建/修改预演前检查 Blender MCP 与场景；仅复用批准的 Playblast 时验证文件，不要求重建场景。
- 提交前核实 LiClick 配置、实际模型标识、模式、素材顺序/类型/数量限制与音频参数。文档与实际入口不一致时核实差异，不能默默降级。

## 1. 导演脚本与运镜标准

先锁定故事、目标风格、画幅、时长和一镜到底/可切镜要求。明确每阶段开始状态、可见动作、结束状态，以及人物与物体交互。

将 Higgsfield 参考拆成可检查属性：起止构图、机位高度、视角/FOV、路径、主体占比、跟随距离、加减速、视差、焦点、运动模糊、衔接与节奏。记录来源 URL/文件、时间段，区分实际观察与推断，不编造精确参数。

描述性运镜不是轨迹文件。没有实际可用轨迹，不承诺一比一复刻。把上述属性作为 Blender 和成片的对照标准，不只写“高级运镜”。

storyboard.json 至少包含 shot_id、duration_sec、target_style、scene_desc、character_action、start_state、visible_result、camera_motion、camera_reference、camera_acceptance、author/provenance。未知焦距标记待定；总时长符合用户预算。

### 导演调度与独立审稿关卡（预演之前）

编剧稿描述故事，导演稿必须进一步解决“为什么此刻这样行动、观众如何看懂”。Codex先按screenplay-expert写稿，再进行一遍独立的导演自审；“独立”指分开的审稿步骤，不冒称另有真人专家、独立模型或代理参与。

- 逐镜交付：人物当前目标、外部阻力、刺激来源、受迫动作、摄影机立场、画面发生的变化及结束状态。对白必须与身体行动及可用时间相容；不安排人物为讲完台词无视当前危险。
- 审稿先检查戏剧效果和可感知因果，再检查技术可行性。问题是“摆拍、平淡、缺乏压力”时，先检查调度、环境事件与威胁升级，不把夸张表情、形容词加码、零穿模或正常解码当成修复。
- 保存导演审稿表：具体缺陷、对应镜头、修改决定、下游验证方式。文字层面的通过只允许进入下一制作环节，不等于预演/成片已经通过视觉验收；尚无视频证据的项目写待验证。
- 用户要求强代入感时，明确观众与人物的空间关系、威胁来向及信息获取顺序；不擅自把既定第三人称改为第一人称，不新增可见摄影师角色。前景遮挡、距离变化、受扰后的重新构图服务于事件，不能靠持续乱抖代替代入感。
- 战争、炮击、无人机袭击或用户要求战场紧迫感时，完整读取并应用[战场紧迫感与代入感导演规则](references/battlefield-immersion.md)。其他题材不强制爆炸、交火或战场调度。
- 预演、首帧与成片逐项复核导演表中的关键事件。首帧/预演仍呈现空旷静场、人物站定等候或威胁缓慢展示时，即使正文写了激烈也不得放行；先修对应输入。不把一个版本的观看方法豁免自动扩大到未来版本。

## 2. Blender 预演与审核

用独立场景保留用户工作，按下述最低有效结构表达主体并建立身份映射，设置相机和动作关键帧，按用户画幅导出 24 fps Playblast，保存 .blend 与版本化视频。

### 通用占位与预演外观残留控制（必做）

适用于本 Skill 的所有影片及真人、3D 写实、2D 卡通等指定风格，不绑定特定人物、道具或剧情。目标是分离运动参考与最终外观，不承诺极简几何、深色材质或提示词能够保证零残留。

- **输入边界**：普通预演视频传递画面，不传递 Blender 对象名、父子层级、骨骼、精确包围盒或动画曲线。只有实际入口支持且确实上传的结构化数据才可声明已传递。绑定与微动必须在编码画面中可读，不能把场景存在关键帧等同于模型能识别动作。
- **最低有效结构**：逐事件确定位置、体积、朝向、接触、支撑、关节与时序要求，再选最简单的代理结构。仅整体走位可用圆柱/胶囊与头部小球；动作依赖四肢、翅膀、轮子或铰接件时保留对应简化分件与关节，不一律删除。不增加与动作无关的五官、衣物纹理、装饰、精细拓扑或写实表面。
- **尺寸与身份**：保留批准主体的整体尺度、相对比例、旋转中心及动作空间；独立运动物体分别建组，不合并为不可分占位体。多人、多物体以稳定对象 ID、起始站位、连续轨迹和外观参考建立映射，复核交叉、遮挡及再次入镜后的身份。需要时用克制辅助纯色并注明不继承；不强制所有主体同形同尺寸同色，也不凭颜色宣称身份绑定成功。
- **道具与连接**：块状物用匹配外轮廓的简单方块，独立开合/旋转部件才分件。细小连接可用有体积的小球标记连接点、简化线段或点列表示路径；需要看清插入、钩挂、穿绕或开合时，保留足以区分接触与未接触的最低几何，不精模装饰。按接近、接触、锁定、随动、释放阶段设定绑定，只在应连接的区间固定相对位置，不让独立物体全程粘连。
- **手持道具与局部微动**：主体用匹配包围盒的方块等简单体，绑定持握空间锚点；按钮、拨杆、旋钮等动作点绑定主体并保留独立局部微动。枪械同样用长条占位体，不制作精细枪管、枪托、实体倍镜或扳机细节；局部标记仅表示位置与微动。均匀无纹理球体原地自转不能提供可靠的可见方向变化，需要时用偏心附属标记、简短方向标记或目标风格关键帧补足，不靠精模解决。小球位移不自动具有“按下/扣动”等动作语义。
- **视觉可读性**：默认中性、克制、哑光平涂，去掉繁杂纹理、强高光、反射及无关光影。主体与背景须有足够对比看清轮廓、接触和运动，不强制纯白，也不强制深色背景加极低对比度；需要接地线索可保留简单阴影。不把“越暗/越抽象越不污染”当结论。上传预演排除 Blender 界面、线框叠加、选择轮廓和调试文字；剧情 UI 单独声明来源与用途。
- **抽象化后的验收**：在实际导出尺寸、帧率和正常播放速度下检查动作可辨性。微动不可辨、关键肢体不存在或接触结构被省略时，记录缺口，补最低结构或目标风格动作参考，不擅自放大行程、改变锁定运镜或时长。未建模部位的碰撞与姿态不能宣称通过；补图不等于完成这些部位的三维检测。

检查路径、穿插、可见性、速度节奏、接触和动作因果；对照 Higgsfield 运镜标准。运镜不满意先改预演，再花积分生成。影视时间拉伸、虚拟跟拍与真实物理行为分开说明，不把戏剧效果伪称严格物理模拟。

正式交付预演或推进下游前，保存 Higgsfield 对照检查表：参考来源与时间码、实际观察到的标准、预演版本与对应时间码/画面证据、PASS / FAIL / UNVERIFIED、修改内容及复检结果。逐项核对构图、机位高度、FOV、跟随距离、路径与视差、加减速、升格衔接和镜头连续性；不适用项写明理由。未实际查看参考、证据缺失或关键项失败时关卡不通过；先修正再复检，不能用参数检查、用户局部认可或最终免责声明代替实际对照。

### 穿模与接触自检（必做）

每版预演必须对完整时间线执行几何自检，并检查实际导出的无声视频；不能仅检查关键帧或依靠提示词中的“禁止穿模”。

检查结论按代理精度限定：整体包围体通过不能外推到未建模的手指、肢体或连接结构。与剧情相关但缺失的结构标记 UNVERIFIED，不冒充 NOT NEEDED；按上节补充最低结构或参考，并保留几何与视觉审核的区别。

- 检查范围：相机及近裁剪面进入人体、道具或地面；人物互穿、肢体穿躯干；脚底穿地、悬空及支撑阶段滑步；手与道具的握持、交接和释放；道具脱手后的独立运动、身体避让与落地；倒地时各身体部位的接触顺序和地面穿透。相机未穿入物体但主体遮满画面、遮住关键动作时，另记可见性失败。
- 在应用动画、约束及修改器后的世界空间几何上逐帧检查。快速运动、擦碰、脱手、命中、倒地和相机近距离掠过区间增加子帧采样或扫掠检测；采样密度按速度、物体尺寸及最小间隙调整，记录检查范围与方法。包围盒重叠只作疑点筛选，须进一步用几何检测和画面证据判断，不能直接等同于穿模。
- 正常握持、衣服贴身、关节连接及剧情明确要求的接触，按“对象对＋时间段＋接触部位＋容差”记录允许范围；不把整个人物或整个镜头排除检测。脱手后的道具不能继续与手或身体粘连。容差按实际场景尺度设置，不靠放宽阈值掩盖可见错误。
- 记录对象、帧号/时间码、异常类型、接触或穿透证据、阈值与例外、修正及复检结果，绑定当前 .blend 和导出视频版本/哈希。没有实际执行自动检测时标记 UNVERIFIED，不声称自动自检通过；抽帧只能作为局部证据，不替代连续动作自然度验收。
- 发现失败后按既有授权修正路径、落点、持握/释放关系、支撑脚或关节动作，再重新导出并复检；保留用户已确认的其他动作和运镜。未解决的关键穿模不放行至付费生成。预演几何通过不保证 Seedance 成片不新增穿模。

### 剧情逻辑与动作连续性自检（必做）

几何零碰撞不等于动作合格。每版分别记录程序检测、剧情/动作画面审核与技术检查，不能相互代替，也不把本节文字当作已安装的自动检测器。

- 从已确认导演脚本建立事件清单：时间段、动作主体、对象、开始条件、执行过程、可见结果。核对人物身份、说话与注视对象、持有物归属和事件顺序；检查是否缺少必要中间动作、结果早于原因或动作主体错位。不得为通过检查改写用户剧情。
- 移动距离必须根据实际场景和现实动作逻辑设计：先核对人物尺度、起止站位、可通行路线与交互所需距离，再分配转身、落脚、起步、行走和停步的时间。优先采用完成交互所需的合理短路径；不能为赶对白或指定关键帧让人物突然冲刺、滑移、绕远路或瞬间跨越房间。下床等支撑转换须先完成必要的摆腿、落脚和重心转移，不能以整体平移代替。
- 对关键移动区间记录实际路径长度、用时、平均/峰值速度，并结合身高比例、步幅、步频、支撑脚和加减速检查可信度；场景单位未标定时不得冒称米或米每秒。单帧位移未超阈值不代表整段步速合理，几何路径畅通也不代表角色有必要走那么远。发现距离与时长不匹配时，在既有授权内调整站位、缩短无必要路径或重新分配节奏，并复核其他人物及镜头衔接；若需要改变锁定总时长、剧情或已确认布局，先取得用户确认，不靠加速硬塞。用户明确要求的冲刺、被击飞或风格化运动按对应事件单独检查动机和因果，不将其高速套用到日常走位。
- 有三维场景时，对完整时间线相邻采样的世界位置、朝向、速度及关键接触关系执行程序筛查，定位瞬移、突然翻转、异常加减速、姿势跳变和持握物脱离。快速交互增加子帧采样；阈值按场景尺度、帧率与批准的动作节奏设定并记录。计划切镜或剧情明确的瞬移按具体事件记录例外，不能据此豁免整个区间。
- 在实际视频中复核接近、转身、伸手、接触、保持与分离是否连续合理；例如拥抱应先走近并转向对方，再形成自然接触，不能瞬间贴身或手臂横穿身体。核对关节姿势、视线、脚步支撑、动作速度及前后镜头的空间关系。示例仅解释检查方法，不强加给无关剧情。
- 因果动作必须看得到起始、过程和结果：触发后才反应，命中后才位移，接触后才破碎；剧情明确要求的同步事件按批准时序核验。镜头遮挡或切镜隐藏关键因果时记为可见性失败，不能仅凭脚本声称动作成立。
- 自动检查输出只是疑点或限定范围的结果；剧情语义和动作自然度仍需画面审核。无实际执行的检测、无法观察的区间和未覆盖的对象必须标为 UNVERIFIED，记录盲区，不声称全自动排除了逻辑错误。
- 每项异常记录对象、时间码、预期与实际、检测方法/阈值、证据、修正和复检结论，绑定当前版本与视频哈希。关键逻辑或动作项 FAIL 时按下述闭环先修预演；不能用零穿模、渲染成功或旧版结论放行新版。生成成片重新进行画面审核，不假称拥有其三维运动数据。

### 每版必检与修正闭环

- 每次导出新版后，必须检查实际导出的视频，不能只查脚本、关键帧或渲染成功。对修改区间及其前后衔接执行 Higgsfield 对照复检，并连续观看本次完整输出，检查修改是否引入其他问题。原参考可复用，不必重复获取，但旧版检查结论不能直接套给新版。
- 检查记录必须绑定当前交付文件路径、版本和 SHA-256；同时记录参考来源、实际查看时间范围、当前视频证据时间码及结论。更换视频文件或修改内容后，旧记录只能作历史证据，不能放行新文件。
- 连续性、加减速及升格恢复必须观看连续片段；几个静帧、预设文字或教程不能证明这些动态项目通过。参考不覆盖某项时继续找匹配参考，不得勉强套用或伪称已检查。用户提供的局部视觉参考另列来源与适用范围，不冒充 Higgsfield 参考。
- FAIL 时执行“定位原因 → 在既有授权内修正 → 重新导出 → 检查实际新版 → 更新记录”，持续处理可修复问题，不停在解释、道歉或询问“要不要继续”。UNVERIFIED 时继续可行的参考查找和独立本地修正；只有确实需要用户输入、额外授权或外部条件时才报告阻塞。
- 默认不把未完成复检的整段视频作为本轮完成结果交付，也不以“仅预演”“未全部通过”等说明绕过关卡。用户明确要求看中间状态时可展示诊断证据，但这不是审核放行，仍继续已授权修正。
- 付费重试仍须新授权；上述闭环只允许在既有权限内执行。更新 Skill、格式校验通过、取得目录或写出检查表均不等于已实际执行视频对照。

场景空间可信度另由 Codex 检查：布局、物体朝向与堆叠、作业通道、角色交互范围和镜头遮挡应符合所选场景逻辑，不为了弹道或镜头把环境摆成无意义的对称障碍阵列。Higgsfield 运镜对照不代替场景审核，也不承担 Blender 布局错误的责任。

预演批准只确认运动与空间，不确认最终外观；保留可复用版本。

## 3. 目标风格参考与审核

支持真人、3D 写实、2D 卡通及用户指定风格。锁定造型、比例、材质/线条、色彩、场景和道具；不把真实毛孔等要求套到所有风格。

逐一列出：预演占位体 → 最终主体 → 对应参考。覆盖后续主要角色、场景与关键道具；开场图不自动覆盖后半段角色。按需要补参考，不机械要求固定张数；缺口明确说明，不靠重复风格词宣称解决。

### 同帧派生与最少充分素材

- **同帧派生**：需要制作首帧或事件关键帧时，优先从已批准的实际预演视频提取对应帧，作为 imagegen 的空间构图参考，结合已批准外观素材生成目标风格图。保留该帧的机位、主体位置、尺度关系、道具朝向、接触与遮挡，不另画一张仅题材相似的场景图。若原帧遮挡关键关系，先定位缺口，不让生图擅自重排空间。纯身份/材质参考不要求伪造对应预演帧。
- **来源记录**：每张派生图记录 `source_previs_path`、`source_previs_sha256`、`source_frame_index`（注明从0或1计数）、`source_time_sec`、`role`（首帧/事件状态/结尾）、采用状态和外观来源。预演更新后，复核受影响派生图，不把旧版图直接当成新版空间依据。按实际提取帧计时；文件名或提示词中写了时间，不等于已完成对应关系验证。
- **成对审图**：并看源预演帧与派生图，核对相机透视、人物/物体数量、位置、朝向、接触和画幅；空间漂移先修图或明确受限的采用范围，不让互相冲突的图和视频一起进入生成。仅换外观时不继承占位几何轮廓。图像一致性检查不能替代预演动态验收。
- **最少充分素材**：先以“批准预演＋覆盖所需外观的首帧/参考图”为候选组合，检查全片覆盖，而非强制只有两份素材。只有后续新主体、新场景、复杂接触或关键姿态存在明确缺口时才增补；已有素材足够则不为凑角色板、道具板或固定张数新增生成。
- **提交删减检查**：素材清单为每份输入写明“解决哪个缺口、适用主体/阶段、移除后损失什么”。职责重复且无独立必要信息的候选不提交，源文件保留；不得擅自移除用户明确锁定要使用的素材。首帧未覆盖后段主体时必须补足，不能以精简为由让模型猜身份。新增图片仍遵守 imagegen、审图及原有授权规则。

对占位视频不能清楚表达的局部操作、复杂接触及关键结束姿态，补充经审核的目标风格关键帧或动作参考，标明主体、事件时间点、开始/接触/结束状态及采用内容。优先复用已批准素材；需要新图仍走 imagegen 和原有审核，本规则不自动启动生成。参考应与预演站位、视角、持有物、时序一致。静态外观图排除站姿，动作关键帧则明确采用所需姿态，不能套用同一排除规则。单张静帧只锚定一个状态，不能证明全过程自然或保证精确时间绑定；入口限制与剩余缺口须记录。

仅使用已批准素材或经授权通过 imagegen 生成的资产图。新生成角色、场景、道具、首帧等资产图统一使用 imagegen；执行前读取可用的 imagegen 技能。工具不可用时说明缺口，不擅自换用 Higgsfield 或其他生图服务。

资产生图默认规则：**较为明亮的自然光线、无杂色、克制细节、无繁杂纹理**。将这四项明确写入生图提示词并在出图后自检；色彩保持干净统一，保留识别角色、道具和场景所需的结构，避免堆砌噪点、污渍和高频纹理。规则适用于本作品选定的真人、3D 写实或 2D 卡通等风格，不把它等同于强制真人化；用户明确指定其他光照或视觉要求时按其要求覆盖。

展示实际图片并记录审核状态。仅用于人物外观的图片排除背景/静态站姿；动作关键帧按上述声明采用必要姿态与接触关系。场景图排除不需要的新布局，光照和风格按本作品统一。更新本规则不自动触发生图或付费视频提交。

## 4. Seedance 2.5 提示词与提交

按 seedance-25-rules 交付提示词正文、独立生成参数和入口待验证项。符号与编号以实际入口为准，同时记录上传顺序，不用文字宣称不存在的硬绑定。

每份素材明确编号/文件、主体、采用内容与排除内容。预演提供路径、时序和空间；风格图提供外观。粗粒度代理体须整体重建，不只是换皮；不误删用户目标风格有意保留的简化造型。

提交清单区分三类职责：运动预演采用可见机位、尺度关系、轨迹、节奏与接触关系，排除占位形状、辅助色及调试元素；外观参考采用主体设计与目标风格；动作关键帧采用指定事件的姿态和交互状态。明确抽象标记的主体与动作含义，不只写“小球动”。预演与图片有冲突时先修正或明确采用范围，不盲目叠加素材；编号、数量与绑定能力以实际入口为准。

预演完整提供动作时序时，按 seedance-25-rules 的正文顺序组织：生成目标一句；主体与事件概括主因果；场景和风格声明目标外观；运镜引用预演并保留必要例外；声音单列；素材职责逐份映射；阶段只列关键状态变化及可见结束状态；保持一致只锁定跨阶段不变量。完整导演脚本、详细时间线、碰撞记录和审核证据保存在项目文件，不逐项复制进生成正文。

提交前执行去重：同一个动作或限制在最相关的位置完整说明一次，其他段落引用对应素材或事件，不在剧情、运镜、阶段、一致性中反复展开同一过程。保留身份、先后因果、用户锁定动作、声音及结束状态；删除重复措辞而非删需求，不设置机械字数上限。预演未表达清楚的动作先按前述规则补结构/参考，不用越来越长的提示词冒充修复。逐项审核主体映射、全片风格覆盖、运镜继承、参数与文件顺序，再经授权提交。

通过 LiClick 提交后立即记录请求、模型/参数、参考资产 ID、request_id、时间与状态。只轮询原任务，不重复提交。

## 5. 联合验收与迭代

分别记录，不能互相替代：

1. 运镜：对照确认预演及 Higgsfield 属性，检查切镜、路径长度、加减速、视差是否偏离。
2. 动作：起始 → 实际执行 → 可见结果完整；接触、空间、数量和身份稳定。
3. 风格：开场、中段、后段、交互及结尾均达目标风格；角色、场景、道具不残留预演占位几何和调试文字。2D 卡通不以写实为标准，3D 写实不等于真人摄影。
4. 技术：解码、时长、比例、分辨率、实际帧率和音轨；技术通过不代表视觉通过。

每条生成候选必须独立重新检查穿模与动作自然度，重点复核相机近身、手与道具、角色交互、落脚、脱手和倒地，不能沿用预演的通过结论。成片通常没有可核验的三维几何，只能记录实际视频中的视觉证据和检查盲区，不伪称执行了三维碰撞检测。对照预演同一事件区间，区分预演已有问题与生成新增问题；前者先修预演，后者再提出针对性素材或生成策略修正。任何新付费重试仍须授权。

残留低模时，核对真实提交的版本、模式、素材及对应阶段，区分现象和待验证原因，不无证据归因 Higgsfield 缺失、模型版本或单一提示词，不保证补图必成功。保留批准运镜，提出针对性的参考/绑定修正；运镜本身失败才改预演。新付费重试必须另获授权。

将占位外观残留、动作信息缺失、身份错配和接触/姿态错误分项记录。不把残留统一归因于模型太精细，不靠删除必要肢体或压暗画面掩盖问题。验证简化策略时保留原版，锁定其他主要条件进行有授权的对照，分别比较全片外观替换与关键动作保真；二者均改善才推广该策略，不凭一次成功宣称所有题材已解决。

保存验收表与 iteration_log：候选、证据时间点、通过/失败/待验证、修改内容、素材版本、用户选择。仅打包用户选择的版本，交付最终 storyboard、素材清单和剪辑说明，区分技术验证与用户接受。
